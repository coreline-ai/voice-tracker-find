- 실제 Samsung 대상의 장시간 녹음·오프라인 STT·Qwen 종료·모델 복구를 release gate로
  검증한다.
- 안정화 뒤 녹음/로컬 AI 보관함, 노트 충돌 해결·검색, 배포 자동화와 조건부 서버 보안을
  순서대로 완성한다.

## 2026-07-25 구현 기록 — Phase 0 완료 / Phase 1 진행

### 고정한 데이터·상태 계약

- P0는 Room column 변경 없이 `chunks.state`의 문자열 상태에 `DELETING`만 추가했다. 따라서
  기존 `recording_sessions`, `chunks`, `upload_attempts` 행을 변환하거나 초기화하지 않는다.
- 수동 재시도는 `RETRY`·`FAILED`에서만 허용한다. 앱 전용 보관 경로의 완성 파일이고 SHA-256이
  일치해야 `READY`로 되돌린다. `CONFLICT`·`QUARANTINED`·진행 중 상태는 재전송하지 않는다.
- 정리는 `DELETING` 표시 → 앱 관리 경로 확인 → 파일 삭제 → DB 행 삭제 순서다. 중단되면 다음
  앱 시작 시 파일이 없으면 DB 행을 마감하고, 파일이 남았으면 `FAILED/DELETE_INTERRUPTED`로
  복구해 사용자에게 보인다.
- Phase 2 Room migration 설계는 다음으로 고정한다: `NoteEntity`는 `localId`를 primary key,
  `remoteId`를 nullable unique key로 분리한다. 기존 `serverId` 기반 row는 `localId`를 새 UUID로,
  `remoteId`를 기존 `serverId`로 옮기고 상세 route·충돌 FK는 `localId`로 전환한다.
  `PENDING_CREATE → SYNCED | FAILED`, `DIRTY → SYNCED | CONFLICT | FAILED`,
  `PENDING_DELETE → 삭제 | FAILED` 전이를 DAO 테스트와 migration fixture로 Phase 2에서 검증한다.

### 이번 구현 범위

- `AppStorageMonitor`가 앱 전용 녹음, 로컬 AI 모델·오디오, 두 Room DB 및 기기 여유 공간을
  계산한다. 녹음 시작은 청크 길이 기준 최소 여유 공간을 확인한다.
- 녹음 탭에 저장공간 현황, 최근 기기 보관함, 동기화 대기함을 추가했다. 업로드 실패·충돌·격리
  항목은 원인을 유지하고, 실패 항목만 원본 검증 뒤 명시적으로 재시도한다.
- 업로드 완료 원본도 기기 보관함에서 사용자 확인 후 정리할 수 있다. 서버의 파일은 이 동작으로
  삭제되지 않으며 자동 삭제는 추가하지 않았다.
- Samsung `SM-S931N`의 빠른 화면 보호기 때문에 Compose 기기 테스트 호스트에 화면 유지 처리를
  추가했다. 이로써 실제 기기 UI 테스트가 화면 전환으로 끊기지 않는다.

- [ ] 로컬 초안 편집 중 앱 재시작/화면 회전에 대비해 편집 초안을 저장 또는 복원한다.

### 자체 테스트

- [ ] 서버 미설정 상태에서 노트 생성·편집 후 앱 재시작해도 내용이 남는다.
- [ ] 연결 복구 후 초안이 한 번만 생성되고 remote ID/revision이 바뀐다.
- [ ] create 응답 직전 앱 종료, 재시도, 중복 실행에서도 중복 서버 노트가 생기지 않는다.
- [ ] 기존 synced/dirty/conflict/archive 노트 migration과 link navigation이 유지된다.

### 완료 조건

- [ ] 네트워크와 서버 설정이 없어도 노트 작성 흐름이 막히지 않는다.
- [ ] 동기화 실패는 데이터 유실 없이 재시도 가능하다.

## Phase 3. Samsung 실기기 release gate

### 목표

- 자동 테스트만으로 보장할 수 없는 녹음·STT·Qwen·모델 lifecycle을 대상 기기에서 수치로 검증한다.

### 구현 태스크

- [ ] `REC-03`: 화면 꺼짐/background 포함 20분 녹음 후 파일·DB terminal·orphan `.part`를 확인한다.
- [ ] `REC-04`: 시작→정지→즉시 시작을 10회 실행해 foreground service·마이크 lease·세션 상태를 확인한다.
- [ ] `STT-01/02`: 비행기 모드 한국어 STT, 화면 이탈·복귀, stop watchdog의 terminal 1회를 확인한다.
- [ ] `QWEN-02/03`: 실제 모델 성공·취소·timeout 후 worker death, 다음 작업 가능 여부, transcript 보존을 확인한다.
- [ ] Qwen 10회 실행에서 peak PSS, host PSS 복귀, worker 종료 시간을 기록한다.
- [ ] `MODEL-01`: install 취소·이어받기·삭제·복구 후 target/staging/backup/partial 상태를 확인한다.
- [ ] QA 증거에는 원본 음성·전사문을 남기지 않고 시간·상태·hash·PSS만 보관한다.

### 자체 테스트

- [ ] Samsung `SM-S931N`에서 feature/app instrumentation failure 0.
- [ ] 20분 녹음 뒤 active session/chunk 0, orphan part 0.
- [ ] STT stop 뒤 5초 안에 terminal 정확히 1회.
- [ ] Qwen 성공/오류/취소/timeout 후 worker death 5초 이내 및 orphan PID 0.
- [ ] Qwen peak PSS 1.5GB 이하, 10회 후 host PSS가 기준선 +128MB 이내로 복귀.

### 완료 조건

- [ ] P0 기능과 실기기 gate가 모두 PASS다.
- [ ] BLOCKED 상태는 PASS로 집계하지 않고 재실행 조건을 남긴다.

## Phase 4. 녹음·로컬 AI 보관함 사용성

### 목표

- 누적된 녹음과 로컬 AI 기록을 실제로 찾고, 고치고, 내보낼 수 있게 한다.

### 구현 태스크

- [ ] 녹음 세션 목록을 청크 단위 최근 5개 표시에서 세션 단위 paged 보관함으로 확장한다.
- [ ] 세션 제목 변경, 날짜/상태 필터, 재생 위치·배속, 안전 삭제와 파일 없음 복구 안내를 제공한다.
- [ ] 로컬 AI 기록에 상세 화면을 추가해 전사문·제목·핵심 요약·할 일을 수정한다.
- [ ] 로컬 AI 기록을 사용자의 명시적 동작으로 일반 노트 생성, 클립보드 복사, Android 공유로 내보낸다.
- [ ] Qwen 모델 관리는 접힌 고급 영역으로 구성하고 설치 공간·진행·오류·삭제 결과를 표시한다.
- [ ] 긴 오류/요약/할 일은 줄 수 제한과 “더 보기”를 제공한다.

### 자체 테스트

- [ ] 100개 이상 세션에서 목록이 paging되고 삭제/재생/필터가 정확하다.
- [ ] 로컬 AI 내용 편집 후 재시작해도 저장값과 source hash 정책이 일관된다.
- [ ] “일반 노트로 저장”은 사용자 확인 없이는 서버 전송을 시작하지 않는다.
- [ ] TalkBack과 글자 크기 1.3에서 주요 버튼/상태/긴 내용이 접근 가능하다.

### 완료 조건

- [ ] 녹음과 로컬 AI 기록이 단순 진단 목록이 아닌 사용 가능한 보관함이 된다.

## Phase 5. 노트 충돌 해결·검색·증분 동기화

### 목표

- 누적 노트를 빠르게 찾고, 충돌을 앱 안에서 데이터 손실 없이 해결한다.

### 구현 태스크

- [ ] 노트 상세에 로컬/서버 버전 비교와 “로컬 유지”, “서버 수용”, “수동 병합”을 추가한다.
- [ ] 충돌 해결은 새 revision을 기준으로 명시적 update를 실행하고 해결 이력을 남긴다.
- [ ] Room FTS 또는 동등한 로컬 검색으로 제목·본문·폴더 검색, 날짜/상태 정렬을 제공한다.
- [ ] 큰 글자에서 노트 필터 칩이 잘리지 않도록 flow/wrap 또는 가로 스크롤을 적용한다.
- [ ] 서버 API가 cursor/updated-since를 지원하도록 확장 가능한 경우 `SyncCursorEntity`를 실제 증분 동기화에 연결한다.
- [ ] 서버 API가 증분 동기화를 지원하지 않는 동안에는 목록 크기 상한·페이지 처리와 전체 동기화 진행 상태를 제공한다.

### 자체 테스트

- [ ] 동일 노트를 로컬/서버에서 각각 수정해 412 conflict와 3개 해결 경로를 검증한다.
- [ ] 검색 인덱스 migration, 한글 검색, 1,000개 노트의 필터/정렬을 검증한다.
- [ ] 증분 cursor 누락·중복·서버 rollback에서 전체 sync fallback이 데이터 삭제를 일으키지 않는다.

### 완료 조건

- [ ] 사용자가 충돌을 이해하고 데이터 손실 없이 해결할 수 있다.
- [ ] 노트 수가 증가해도 목록과 동기화 진행을 이해할 수 있다.

## Phase 6. CI·release·조건부 서버 운영

### 목표

- 사람의 로컬 환경에만 의존하지 않고, 선택한 배포 방식에서 일관되게 빌드·검증·운영한다.

### 구현 태스크

- [ ] GitHub Actions에 Python receiver test/ruff와 Android unit/lint/release assemble을 분리 추가한다.
- [ ] QA APK와 unsigned release artifact의 SHA-256, versionCode, ABI, 테스트 결과를 CI artifact로 남긴다.
- [ ] signing key는 저장소에 넣지 않고 CI secret 또는 승인된 secure storage로 주입한다.
- [ ] debug/deviceQa/release의 서버 URL·cleartext·서명·artifact 정책을 문서화한다.
- [ ] 서버 직접 노출 프로필을 `insecure_debug`, `native_tls`, `trusted_proxy`로 명확히 분리한다.
- [ ] standalone Receiver를 직접 노출하는 경우 bounded concurrency와 초과 시 `503 + Retry-After`를 적용한다.
- [ ] public CA/reverse proxy 배포에서는 proxy의 TLS·rate limit 책임을 문서화하고 Python의 중복 TLS 강제를 피한다.
- [ ] self-signed Android trust/pin과 브라우저 APK ticket은 선택한 배포 프로필이 필요로 할 때만 별도 계획으로 분리한다.

### 자체 테스트

- [ ] 새 clone에서 CI가 Android/Python 검증과 artifact 생성까지 성공한다.
- [ ] release build가 HTTP 주소·debug signing·토큰 평문을 포함하지 않는다.
- [ ] direct Receiver 동시 연결 초과 시 기존 요청의 파일/DB 정합성을 깨지 않고 빠르게 거절한다.
- [ ] redirect 응답에서 Authorization을 가진 두 번째 요청이 발생하지 않는다.

### 완료 조건

- [ ] 배포 후보의 재현 가능한 빌드·검증·서명 절차가 있다.
- [ ] 실제 배포 프로필에 필요한 서버 보안 조건만 release gate로 적용된다.

## 잔여 리스크 / 후속 과제

- Qwen은 arm64·충분한 RAM·열/배터리 조건을 만족하는 기기에서만 생성형 요약을 제공한다.
- 시스템 STT의 한국어 오프라인 품질과 언어팩 설치 상태는 제조사/OS에 의존한다.
- 장기 보존/자동 삭제/백업·복원과 앱 잠금은 사용자 데이터 정책을 확정한 별도 계획에서 다룬다.
- 서버가 매우 많은 노트 또는 다중 사용자 동시 편집을 지원해야 하면 Phase 5의 증분 API와
  충돌 정책을 별도 성능 계획으로 확장한다.
