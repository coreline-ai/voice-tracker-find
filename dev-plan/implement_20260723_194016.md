# implement_20260723_194016.md

작성 일시: `2026-07-23 19:40:16 KST`

이 문서는 Thinktank Recorder의 Flutter iOS MVP 개발 범위를 고정하고, 구현이 Android 1:1 복제나 iOS 비지원 기능으로 확장되지 않도록 하기 위한 작업 문서다.

## 개발 목적

기존 Android APK의 사용자 가치를 iOS 공개 API와 App Store 정책 안에서 재구현한다.

목표 사용자 흐름:

```text
사용자가 녹음을 시작한다
→ 화면 잠금 중 녹음을 지속한다
→ M4A 청크를 앱 sandbox에 저장한다
→ 파일 기반 백그라운드 업로드 큐에 등록한다
→ 기존 PC 수신기와 Python 파이프라인이 처리한다
→ Flutter 앱에서 생성된 노트를 조회·편집한다
```

완료 시점에는 물리 iPhone과 실제 Windows PC 수신기 사이의 녹음·업로드·노트 동기화가 검증되어야 한다.

## 개발 범위

- 프로젝트 하위 `mobile/`에 Flutter iOS 앱을 신규 생성한다.
- Flutter가 화면, 상태, 로컬 DB, 노트 기능을 담당한다.
- Swift 브리지가 오디오 녹음, background URLSession, TLS pin, Keychain, iOS 수명주기를 담당한다.
- 사용자가 직접 시작하고 정지하는 M4A/AAC 녹음을 구현한다.
- 화면 잠금 뒤에도 진행 중인 녹음이 지속되도록 구현한다.
- 기본 20분, 최소 5분 단위의 녹음 청크 회전을 구현한다.
- 녹음 파일의 영속 업로드 큐와 백그라운드 파일 업로드를 구현한다.
- 기존 bearer 인증과 `/upload`, `/notes` 계약을 사용한다.
- 서버 주소, 사용자 ID, token, SPKI pin 설정 및 연결 검증을 구현한다.
- 노트 목록, 폴더 그룹, Markdown 렌더링, 위키링크, 기존 노트 편집·삭제를 구현한다.
- 기존 Python 수신기에 iOS 업로드 안전성에 필요한 최소 계약 보완과 테스트를 추가한다.
- 마이크, 로컬 네트워크, 알림, background audio와 App Store 제출 설정을 구성한다.
- 실제 iPhone, 화면 잠금, 네트워크 단절, 오디오 인터럽트, 실제 PC 수신기를 포함한 E2E 검증을 수행한다.

## 문서 기반 제약 사항

- 현재 모바일 원본은 Flutter 프로젝트가 아니라 컴파일된 Android APK다.
- APK 디컴파일 결과는 동작 참조로만 사용하고 프로덕션 소스에 복사하지 않는다.
- iOS 녹음은 사용자가 명시적으로 시작해야 한다.
- 백그라운드는 이미 시작된 녹음과 이미 등록된 파일 전송의 지속에 한정한다.
- 앱은 녹음 중임을 화면과 시스템 상태에서 명확히 표시해야 한다.
- background task는 정확한 실행 시각이나 주기를 전제로 설계하지 않는다.
- 기존 수신기는 `Content-Length`가 없는 요청에 411을 반환한다.
- 업로드 파일은 최대 2 GiB이며 서버는 `.part` 파일에 받은 뒤 원자적으로 교체한다.
- 기존 노트 PUT은 서버에 이미 있는 노트만 갱신하며 신규 노트는 404다.
- 현재 배포 기본값은 LAN HTTP이나 iOS 구현은 광범위한 ATS 예외를 사용하지 않는다.
- 마이크, background audio, background URLSession은 물리 iPhone에서 검증해야 한다.

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.
- 구현 중 발생한 이슈는 해당 Phase에서 수정하고 기록한다.
- 체크박스 상태를 실제 진행 상태와 맞게 업데이트한다.
- 문서에 없는 범위 확장은 하지 않는다.
- 요구사항이 불명확하면 가능한 케이스를 나누고 확인 후 진행한다.
- 한 기능은 유지보수 가능한 최소 책임 단위로 나누고, 각 단위의 역할과 경계를 계획에 적는다.
- 계획 밖 옵션·확장·부가 기능을 만들기 위한 분리는 하지 않는다.
- 공통화는 계획 범위 안의 중복을 줄일 때만 수행하고 과도한 추상화는 피한다.
- 기존 프로젝트 API, Apple 공식 SDK, Flutter 표준 기능을 우선하고 새 의존성은 범위상 필요할 때만 추가한다.
- 오디오, background URLSession, trust challenge를 범용 Flutter 패키지 하나에 전적으로 위임하지 않는다.
- token과 pin을 로그, URL query, analytics, crash message에 남기지 않는다.
- 업로드 완료는 HTTP 성공뿐 아니라 해당 로컬 큐 레코드와 서버 충돌 정책까지 확인한 뒤 확정한다.
- 시뮬레이터 성공을 백그라운드 녹음·업로드 완료 판정으로 사용하지 않는다.
- 서버 계약 변경은 기존 Android 클라이언트 호환 테스트를 통과해야 한다.
