# implement_20260813_205318.md

작성 일시: `2026-08-13 20:53:18 KST`

이 문서는 기존 제품 식별자를 새 브랜드 `AI R Voice`와 Android 패키지
`com.coreline.ai.voice`로 전환하는 범위를 고정하고, Android·웹·Python 서버·배포·문서를
다른 작업자가 이어서 구현할 수 있도록 단계와 검증 기준을 정의한다.

## 개발 목적

- 사용자에게 노출되는 제품명을 모든 활성 화면과 운영 문서에서 `AI R Voice`로 통일한다.
- Android release application ID를 `com.coreline.ai.voice`로 확정하고 모든 소스 package,
  namespace, 테스트, AIDL, Room schema 경로를 일치시킨다.
- 웹 콘솔, Python 배포 패키지, 런타임 경로, 스크립트와 배포 산출물을 새 브랜드 체계로
  전환한다.
- 기존 녹음·STT·Gemma·OAuth cloud-first/local-fallback 동작과 보안 경계를 바꾸지 않는다.
- 과거 제품명과 식별자가 활성 코드에 우발적으로 남지 않도록 허용 목록 기반 검증 gate를 둔다.
- 앱 ID 변경, 서버 데이터 경로 변경, 웹 저장 키 변경으로 발생할 수 있는 데이터 단절을 명시적
  정책과 테스트로 통제한다.

## 데이터·호환성 정책

### Android

- `com.coreline.ai.voice`는 OS 기준 신규 앱이다. 기존 `com.thinktank.recorder.next`, `.qa`,
  `.debug`의 private data는 자동 승계되지 않는다.
- 정식 배포 전 rebrand라는 전제에서 새 package는 clean start로 확정한다.
- 기존 package를 자동 uninstall하지 않으며 사용자가 검증 후 별도로 제거한다.
- 새 `.qa` package 내부에서는 `adb install -r` 재설치 시 DB, 설정, 다운로드 모델이 보존되어야 한다.
- Room table/column과 migration 1→10은 유지한다. Room schema 파일은 새 database class의 정규
  package 경로로 옮기되 과거 schema version을 삭제하거나 새 schema로 덮어쓰지 않는다.
- application ID 변경으로 OAuth SDK의 encrypted profile storage가 새 sandbox에서 시작되는 것을
  정상 동작으로 본다. 실계정 profile 자동 이전은 하지 않는다.

### Python/PC 서버

- canonical default는 `~/.airvoice`와 `~/ai-r-voice-vault`다.
- 기존 `~/.thinktank` 데이터가 있고 새 경로가 비어 있으면 명시적 migration 안내 또는 전용
  migration command를 제공한다. 실행 전 source/target과 이동 대상을 표시하고 기본 동작은
  copy/rename 중 데이터 유실이 없는 방식을 택한다.
- 새 경로에 데이터가 이미 있으면 자동 merge하지 않고 충돌 오류와 수동 조치 방법을 출력한다.
- 환경변수로 기존 경로를 명시한 사용자는 그대로 사용할 수 있다.
- legacy scheduled task를 자동 삭제하지 않는다. 새 task 등록 후 중복 실행 방지를 검증하고
  legacy unregister 명령을 런북에 제공한다.

### 웹

- 새 sessionStorage key를 canonical로 사용한다.
- 새 key가 없고 legacy key만 있으면 동일 origin에서 값을 1회 복사한 뒤 새 key를 사용한다.
- token 값을 로그, DOM text, telemetry에 출력하지 않는다.
- migration 호환 코드와 테스트 외 사용자 화면에는 과거 브랜드가 노출되지 않아야 한다.

## 과거 명칭 허용 목록 원칙

최종 `rg` 검사는 저장소 전체에서 무조건 0건을 요구하지 않는다. 아래 범주만 과거 명칭을
허용하고, 나머지 활성 코드·리소스·운영 문서는 0건을 요구한다.

1. `dev-plan/`의 완료된 과거 계획
2. 날짜가 고정된 과거 `docs/qa/` 보고서, UIAutomator XML, 스크린샷 설명
3. 독립 SDK의 원본 `PROVENANCE.md`, license, third-party notice에 기록된 사실
4. legacy PC data/web key migration을 위한 격리된 compatibility constant와 그 테스트
5. 변경 전/후를 설명하는 이번 계획과 migration 문서

허용 목록은 파일 경로와 필요한 literal을 검사 script에 명시하며, 새 활성 코드가 광범위한
exclude pattern 뒤에 숨지 않게 한다.

- Android application ID 변경으로 기존 앱 private data는 자동 이전되지 않는다. 출시 사용자가 생긴

- 과거 QA 증적과 provenance에는 역사적 이름이 의도적으로 남으므로 저장소 전체 문자열 0건을
  완료 기준으로 사용하지 않는다.
