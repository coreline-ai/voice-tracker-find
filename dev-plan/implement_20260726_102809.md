# implement_20260726_102809.md

작성 일시: `2026-07-26 10:28:09 KST`

이 문서는 1번 탭의 완료 녹음을 4번째 로컬 AI 탭에서 선택하고, 기기 안에서 PCM으로 정규화한
뒤 Android 시스템 온디바이스 STT로 전사·요약하는 작업의 범위를 고정한다. Samsung 실기기
검증까지 수행했으며, 파일 입력 STT의 production 활성화는 그 실증 결과에만 따라 결정한다.

## 개발 목적

- 1번 탭에서 안전하게 끝난 녹음 원본을 4번째 탭에서 선택해 전사·요약할 수 있게 한다.
- 원본 M4A/WAV는 변경하거나 삭제하지 않고, 분석용 16 kHz mono PCM 임시 파일만 생성한다.
- 전사 원문, 스크롤되는 진행 표시, 실제 요약 엔진 표기를 기존 로컬 AI 기록 카드에 일관되게
  저장·표시한다.
- Moonshine·클라우드 STT·클라우드 LLM을 재도입하지 않고 Android 시스템 온디바이스 STT만
  사용한다.

## 개발 범위

1. 4번째 탭에서 1번 탭의 **완료된** 녹음 청크를 선택하는 UI와 앱→feature 경계 계약을 추가한다.
2. M4A(AAC)/PCM WAV를 `PCM 16-bit · mono · 16 kHz`로 정규화하는 로컬 변환기를 추가한다.
3. Android 13(API 33) 이상에서 PCM 파일을 시스템 온디바이스 STT에 전달하는 별도 파일 전사
   엔진을 추가한다.
4. 파일 전사 결과를 기존 `ondevice_sessions` 전사·요약·기록 카드 흐름에 저장한다.
5. 원본 검증, 임시 파일 정리, 취소, DB migration, 자동 테스트와 실기기 release gate를 추가한다.

## 제외 범위

- Moonshine, Whisper, Vosk 등 다운로드형/별도 STT 엔진 추가
- 클라우드 STT·LLM, 서버 업로드, 음성·PCM·전사문 외부 전송
- 녹음 중 청크 또는 `.part` 파일의 선택·분석
- 1번 탭 원본 파일 편집·이동·자동 삭제, 통화 녹음 폴더·전체 저장소 탐색
- 다수 청크 병합, 장시간 전체 세션을 하나의 전사로 결합하는 기능
- 파일 입력 STT 미지원 기기에서 마이크 입력으로 조용히 전환하는 우회 동작

### STT SDK 제약과 활성화 기준

- 현재 `AndroidOnDeviceSpeechEngine`은 마이크용 `createOnDeviceSpeechRecognizer()`와
  `startListening()`만 사용한다. 파일 전사에 그대로 섞지 않고 별도 `SystemPcmFileSpeechEngine`을
  만든다.
- `RecognizerIntent.EXTRA_AUDIO_SOURCE`는 API 33부터 PCM source descriptor를 받을 수 있지만,
  인식기 구현이 지원하지 않으면 마이크를 열 수 있다. 따라서 파일 전사 버튼은 API 33 미만에서
  비활성화하고, 지원 확인·실기기 검증을 통과하기 전에는 production 활성화하지 않는다.
- 파일 전사에서 source가 무시된 경우 마이크 전사 결과를 저장해서는 안 된다. 지원 불명/미지원은
  명시적 오류로 끝내며 실시간 STT 경로로 자동 전환하지 않는다.
- 시스템 인식기의 실제 파일 입력·`onSegmentResults` 동작은 Samsung 구현체 의존이므로 자동
  테스트 PASS만으로 활성화 판정을 내리지 않는다.

### 권장 데이터·작업 흐름

1. app gateway가 완료 원본의 state·관리 경로·SHA를 검증하고 feature 임시 경로로 snapshot을 복사한다.
2. feature가 snapshot을 PCM 16-bit/mono/16 kHz raw stream으로 변환한다. WAV가 이미 같은 형식이면
   헤더를 제외한 payload를 복사한다.
3. 파일 STT 엔진이 PCM descriptor와 channel/sample-rate/encoding을 전달한다. segment callback은
   기존 스크롤 전사창에 누적한다.
4. 결과는 새 로컬 AI 세션에 저장하고, 현재 선택된 Kotlin/Qwen 요약 흐름을 그대로 호출한다.
5. source snapshot·PCM은 성공/실패/취소/앱 종료 복구에서 삭제한다. DB에는 원본 식별자·표시 정보만
   남긴다.

## 문서 기반 제약 사항 / 결정 기록

- 시스템 온디바이스 STT 단일 정책은 유지한다. 파일 전사만 추가하며 새 STT 모델은 추가하지 않는다.
- 입력은 앱 내부 `recordings/`에서 repository가 검증한 완료 청크만 허용한다.
- `audioPath`는 계속 feature 소유 녹음 파일 전용이다. 1번 탭 path는 저장하지 않는다.
- API 33 미만과 파일 입력 미검증 단말은 “파일 전사 미지원”으로 표시한다. 사용자의 원본을
  마이크로 재생해 우회하지 않는다.
- 파일 전사가 지원되는지 확정하기 전, UI에는 “기기 확인 필요” 상태를 노출하고 production 기본
  활성화 여부를 보류한다.
- 요약은 기존 선택 방식만 사용하고, 완료 세션에는 실제 결과의 `summaryEngine`을 표시한다.
