이 문서는 Kotlin + Jetpack Compose Android 앱에 **네트워크를 사용하지 않는 온디바이스 STT·요약 전용 4번째 탭**을 추가하기 위한 개발 범위를 고정하고, 구현이 클라우드·서버 처리 방향으로 확장되지 않도록 하기 위한 작업 문서다.

## 개발 목적

- 기존 `녹음 · 노트 · 설정` 3탭에 `로컬 AI` 4번째 탭을 추가한다.
- 음성, 전사문, 요약문을 외부 서버로 보내지 않고 Android 단말 안에서만 처리한다.
- 사용자가 STT 엔진과 요약 엔진을 각각 선택할 수 있게 한다.
- 경량 기본 모드는 별도 모델 없이 제공하고, 고정밀 모드는 오프라인 모델 팩을 가져와 사용한다.
- STT와 LLM을 순차 로딩하고 네이티브 추론을 격리하여 앱 용량·메모리·발열 부담을 통제한다.
- 4번째 탭 데이터가 기존 `SyncRepository`와 Receiver 업로드 대상에 들어가지 않도록 저장·상태 경계를 분리한다.

### 네트워크 금지 경계

- 이번 계획의 네트워크 금지는 **음성·전사·요약 처리 파이프라인**에 적용한다.
- 예외는 사용자가 모델 관리 화면에서 명시적으로 시작한 승인된 모델 파일 HTTPS GET뿐이다.
- 모델 다운로드 요청에는 음성, 전사문, 요약문, 세션 식별자, 서버 토큰을 포함하지 않는다.
- 모델 설치가 끝난 뒤 Moonshine·Qwen 추론 서비스는 네트워크 클라이언트와 URL을 전달받지 않는다.
- 기존 세 탭은 현재 Receiver 연결과 노트 동기화를 유지하므로 앱 Manifest의 `INTERNET` 권한은 남는다.
- 따라서 “APK 전체가 네트워크를 전혀 사용하지 않는다”가 아니라, “4번째 탭의 음성·전사·요약 데이터가 네트워크를 사용하지 않고 동기화 대상에도 들어가지 않는다”를 보장한다.
- 앱 전체 네트워크 금지가 필요해지면 `offlineAi` product flavor를 별도 계획으로 작성하며 이번 구현에 혼합하지 않는다.

## 엔진 조합

| 모드 | STT | 요약 | 추가 모델 저장공간 예상 | 동작 |
|---|---|---|---:|---|
| 초경량 | Android 온디바이스 STT | Kotlin 추출형 | 없음 | 실시간 발화 후 즉시 경량 요약 |
| 경량 AI | Android 온디바이스 STT | Qwen 로컬 | 약 563MB | 시스템 STT 결과를 로컬 LLM으로 요약 |
| 안정형 | Moonshine 로컬 | Kotlin 추출형 | 약 60~110MB | 로컬 음성 파일을 독립 STT로 전사 |
| 완전 로컬 AI | Moonshine 로컬 | Qwen 로컬 | 약 650~750MB | 전사와 생성형 요약 모두 앱 관리 모델로 처리 |

### 엔진별 기능 차이

- Android 온디바이스 STT는 `API 31+`에서 런타임 지원 여부를 확인하고 `createOnDeviceSpeechRecognizer()`만 사용한다.
- Android 온디바이스 STT가 지원되지 않거나 한국어 로컬 모델이 준비되지 않은 경우 온라인 가능 일반 인식기로 폴백하지 않는다.
- Android 온디바이스 STT는 OS 음성 인식 서비스가 마이크를 사용하는 **라이브 받아쓰기 모드**로 제공한다. 임의의 기존 음성 파일 입력을 같은 기능으로 약속하지 않는다.
- Moonshine은 앱이 로컬에 저장한 PCM/WAV 입력을 처리하는 **파일 전사 모드**로 제공한다.
- Kotlin 추출형 요약은 원문 문장을 재배열·선별하며 원문에 없는 내용을 생성하지 않는다.
- Qwen 요약은 제목·핵심 요약·할 일을 생성하지만 결과를 원문과 함께 표시하고 사용자가 수정·삭제할 수 있게 한다.

## 모델 팩 계약

모델은 서로 독립된 두 개의 서명 모델 팩으로 제공하며 모델 관리 GUI 다운로드와 오프라인 파일 가져오기가 같은 설치·검증 경로를 사용한다.

```text
thinktank-moonshine-ko-v1.ttmodel
thinktank-qwen-summary-ko-v1.ttmodel
```

각 팩의 최소 manifest:

```json
{
  "schemaVersion": 1,
  "packId": "moonshine-ko",
  "version": "1.0.0",
  "engine": "sherpa-onnx",
  "abi": ["arm64-v8a"],
  "minSdk": 26,
  "signatureAlgorithm": "ECDSA_P256_SHA256",
  "files": [
    {
      "path": "model.onnx",
      "size": 0,
      "sha256": ""
    }
  ],
  "licenses": [
    "licenses/MODEL-LICENSE.txt"
  ]
}
```

- 팩에는 `manifest.json`과 분리된 `manifest.sig`를 포함하고, 앱에 고정한 배포 공개키로 서명을 먼저 검증한다.
- 앱에는 승인된 모델 ID·버전·크기·HTTPS URL·SHA-256만 포함한 고정 카탈로그를 번들하며 임의 URL 입력을 제공하지 않는다.
- 다운로드는 `.part` 파일, HTTP Range/ETag, Wi-Fi 우선 WorkManager를 사용하고 완료 후에만 설치 단계로 전환한다.
- ZIP 기반 입력 스트림을 임시 전체 복사하지 않고 대상 임시 디렉터리에 스트리밍 해제한다.
- 모든 파일의 상대 경로, 허용 파일 수, 개별 크기, 전체 크기, SHA-256을 검사한다.
- `..`, 절대 경로, symlink, 중복 경로, 선언되지 않은 파일을 거부한다.
- 검증 완료 후 임시 디렉터리를 모델 버전 디렉터리로 원자적 전환한다.
- 설치 실패 시 기존 정상 모델은 유지하고 불완전 임시 파일만 정리한다.
- 모델과 런타임 라이선스가 상업적 배포 조건에 맞는지 확인하기 전 release 산출물에 포함하지 않는다.

- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.
- 구현 중 발생한 이슈는 해당 Phase에서 수정하고 기록한다.

- 새 네이티브 의존성은 라이선스·ABI·APK 크기·실기기 동작을 Phase 1에서 검증한 뒤 확정한다.

- 사용자가 녹음 또는 요약을 시작하지 않은 상태에서 백그라운드 추론을 자동 시작하지 않는다.
- 음성·전사·요약 내용은 테스트 로그와 개발 계획에 기록하지 않는다.
- 기존 서버 동기화 기능의 회귀를 발생시키지 않는다.

| 리스크 | 영향 | 대응 |
