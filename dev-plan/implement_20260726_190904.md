# implement_20260726_190904.md

작성 일시: `2026-07-26 19:09:04 KST`

이 문서는 4번째 탭에서 Qwen 요약이 실패했을 때 Kotlin 빠른 요약으로 대체되는 현재 동작을
사용자가 정확히 식별·복구할 수 있게 하는 범위를 고정한다. Qwen, STT, 모델의 기능 범위를
넓히지 않으며 원문은 기기 밖으로 전송하지 않는다.

## 개발 목적

- Qwen 성공·실패·Kotlin 대체 결과를 혼동 없이 표시한다.
- 실패 원인을 원문·프롬프트·모델 경로 없이 안전한 분류 코드와 짧은 안내로 남긴다.
- Qwen 실패 뒤 보존된 빠른 요약을 사용자가 명시적으로 Qwen으로 다시 실행할 수 있게 한다.
- 고정 Samsung에서 한국어 음성 샘플 1건의 PCM → SenseVoice → Qwen 전체 엔진 경로를 회귀 검증한다.

## 개발 범위

1. Qwen 예외를 `모델/자원/시간초과/Binder·worker/응답형식/알 수 없음`으로 안전하게 분류한다.
2. Qwen 실패 시 실제 저장 엔진(`Kotlin 빠른 요약`)과 대체 사유를 세션 결과에 보존·표시한다.
3. 전사문이 보존된 대체 세션에서만 `Qwen으로 다시 요약`을 제공하고, 기존 요약을 덮어쓰기 전
   세션 상태·동시 작업·모델 준비 상태를 다시 확인한다.
4. 삼성 실기기에서 오프라인 한국어 TTS로 만든 단일 테스트 녹음 파일을 사용해
   `WAV → 16 kHz PCM → SenseVoice → Qwen`을 실제 실행하고, 원본·PCM·전사문을 즉시 정리한다.

## 제외 범위

- Qwen 모델 교체, context/window·출력 token 정책 변경, 클라우드 요약 또는 네트워크 사용
- STT 모델·VAD·실시간 STT·일반 녹음 UI의 동작 변경
- 사용자 원본 녹음·전사문을 PC, 로그, 서버로 반출하는 QA
- 자동 재시도, 백그라운드 반복 실행, 실패 세션의 자동 삭제

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.
- Qwen 실패 원문·prompt·raw model output은 로그·DB 진단값·UI 오류에 넣지 않는다.
- 실제 저장된 요약 엔진은 결과 모델의 값으로만 표시한다. 선택값만으로 Qwen 성공을 표기하지 않는다.
- 재시도는 사용자의 명시적 동작으로만 시작하며, STT와 Qwen native 작업은 기존 `ResourceArbiter` 직렬화를 유지한다.
- Samsung 실기기 대상은 `R3CY40PXCAP` (`SM-S931N`)으로 고정한다. PD20은 사용하지 않는다.
- QA fixture는 앱 private cache에만 만들고 성공·실패·취소 모두에서 원본 WAV·PCM·전사문을 삭제한다.
