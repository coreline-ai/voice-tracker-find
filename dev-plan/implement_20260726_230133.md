# implement_20260726_230133.md

작성 일시: `2026-07-26 23:01:33 KST`

이 문서는 4번째 탭의 온디바이스 한국어 요약 실패 원인을 제거하고, Qwen·EXAONE·
Gemma를 선택 가능한 모델 팩으로 제공하기 위한 개발 범위를 고정한다. 모델이 실패했는데
Kotlin 대체 결과를 LLM 성공으로 보고하는 문제를 금지하고, 기존 1분 7초 녹음으로 실제
엔진별 결과를 검증하는 것을 완료 기준으로 삼는다.

## 개발 목적

- Qwen3.5에 잘못 적용된 `/no_think` 지시와 제어 불가능한 생성 설정을 제거한다.
- `llama.cpp` 추론 계층에서 모델별 sampling, seed, token 상한, JSON grammar를 제어한다.
- 하나의 소형 모델에 구간 선택·요약·제목·할 일·근거 ID를 동시에 요구하지 않고,
  핵심 구간 선택과 요약 생성을 분리한다.
- 한국어 기본 후보로 `EXAONE 4.0 1.2B Q4_K_M`을 추가하고 실제 기기 결과로 기본
  모델 승격 여부를 결정한다.
- 경량 선택지로 `Gemma 3 1B LiteRT-LM`을 추가하되 한국어 품질 검증 전에는 기본
  모델로 지정하지 않는다.
- 사용자에게 요청 모델, 실제 실행 모델, fallback, 품질 실패 원인을 정확히 표시한다.
- 모델은 APK에 포함하지 않고 Wi-Fi에서 사용자가 선택해 다운로드·설치·삭제할 수 있게 한다.

## 개발 범위

1. 현재 Qwen 호출·프롬프트·품질 게이트의 진단 계약 수정

3. 원문 구간 선택 → 선택 구간 압축의 2단계 요약 파이프라인
4. `EXAONE 4.0 1.2B Q4_K_M` 공식 GGUF 모델 팩
5. `Gemma 3 1B`용 공식 LiteRT-LM Kotlin 런타임 및 모델 팩
6. Qwen·EXAONE·Gemma 선택/다운로드/설치 상태 UI
7. 요청·실제 모델, 모델 버전, prompt/정책 버전, 검증 실패 코드 영속화
8. 단위·native·Room·Compose·실기기 A/B 및 회귀 테스트

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.
- 구현 중 발생한 이슈는 해당 Phase에서 수정하고 기록한다.
- 체크박스 상태를 실제 진행 상태와 맞게 업데이트한다.
- 문서에 없는 기능·모델·리팩터링을 추가하지 않는다.
- 요약 본문을 임의 글자 수로 잘라 품질 검사를 통과시키지 않는다.
- 실제 실행 엔진이 요청 엔진과 다르면 LLM 성공으로 보고하지 않는다.
- 원문·오디오·LLM raw 출력은 logcat, PC 파일, 문서, 테스트 리포트에 남기지 않는다.
- 진단에는 violation code, 글자 수, 실행 시간, 모델 ID, prompt/정책 버전만 사용한다.
- 모델 다운로드만 네트워크를 허용하며 추론 시 네트워크 사용을 금지한다.
- 모델 다운로드는 Wi-Fi 조건에서만 시작·재개하고 설치 완료 모델은 앱 업데이트 후 재다운로드하지 않는다.
- 기존 `.qa`에는 동일 서명 APK를 `adb install -r`로만 적용한다.
- 자동 instrumentation은 `.deviceTest` 격리 패키지에서만 실행한다.
- 실기기는 Samsung `SM-S931N` (`R3CY40PXCAP`)만 사용하고 PD20은 사용하지 않는다.
- 실기기 테스트는 모델별 최대 3회로 제한하고 같은 실패를 목적 없이 반복하지 않는다.
- 모델의 기본값 승격은 기존 1분 7초 녹음의 A/B 통과 결과를 문서에 기록한 후에만 한다.

## 성공 판정 계약

- `requestedModelId == actualModelId`일 때만 해당 LLM 성공으로 집계한다.
- fallback 결과는 `actualEngine=EXTRACTIVE_KOTLIN`과 실패 코드를 반드시 저장한다.
- 요약은 1개를 기본으로 하고 서로 독립된 핵심이 있을 때만 최대 2개를 허용한다.
- 요약 전체는 원문보다 짧고, 목표 압축률은 원문의 `10~20%`, 절대 상한은 100자로 한다.
- 신규 인명·날짜·수치·영문 고유어를 만들지 않는다.
- 문장 중간 절단, `...`, `…`, 미완성 종결을 허용하지 않는다.
- 선택한 원문 구간 ID가 유효하고 요약의 근거 구간으로 보존되어야 한다.
- 기존 1분 7초 녹음에서 실제 LLM 결과가 Kotlin fallback 없이 3회 연속 통과해야 한다.

## Phase 3. 2단계 요약 파이프라인

### 목표

- 소형 LLM에 복합 지시를 한 번에 요구하지 않고 근거 선택과 문장 압축을 분리한다.

### 구현 태스크

- [ ] `KoreanTranscriptSegmenter`가 생성한 구간 중 핵심 후보를 Kotlin에서 4~8개로 축소한다.
- [ ] 1차 LLM 호출은 유효한 `selectedIds`만 반환하도록 제한한다.
- [ ] 선택된 구간만 2차 LLM 호출에 전달해 핵심 요약 1문장, 필요 시 최대 2문장을 생성한다.
- [ ] 제목은 선택 구간의 핵심어 기반 Kotlin 생성 또는 별도 제한 호출 중 하나로 고정한다.

## 잔여 리스크 / 후속 결정

- EXAONE 공식 문서의 Chat Template 주의 사항이 현재 llama.cpp `b10107`에서 해소됐는지

  통과 전에는 기본 모델로 지정하지 않는다.

  않고 CPU 기준 안정화 후 별도 판단한다.

  constrained decoding 실패 원인을 먼저 수정한다.
