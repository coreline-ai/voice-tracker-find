# implement_20260726_215106.md

작성 일시: `2026-07-26 21:51:06 KST`

이 문서는 4번째 탭의 핵심 요약을 글자 수 절단 방식에서 원문 근거 기반 품질 검증
방식으로 교체하고, 실제 기기 QA가 사용자의 기록·모델을 초기화하지 않도록 패키지를
구조적으로 분리하기 위한 작업 문서다.

## 개발 목적

- SenseVoice 전사문에 문장부호가 없어도 한국어 발화 단위로 분리해 요약 입력을 구성한다.
- Qwen 결과를 글자 수로 잘라 저장하지 않고, 완결성·압축률·원문 근거·중복을 검증한다.
- 품질 기준을 통과하지 못한 Qwen 결과는 1회 교정 재생성하고, 재실패 시 완전한 원문
  구간으로 구성된 Kotlin 추출형 요약을 저장한다.
- 결과 카드에 요청 엔진, 실제 엔진, fallback 여부, 요약 정책 버전을 명확히 표시한다.
- 기존 `com.thinktank.recorder.next.qa`의 기록과 다운로드 모델은 유지하면서 자동
  instrumentation 전용 패키지를 별도 application ID로 분리한다.

## 개발 범위

1. 한국어 STT 전사문 구간 분리와 추출형 요약 개선
2. Qwen 구조화 결과 parser와 `SummaryQualityGate` 구현
3. Qwen 품질 실패 1회 교정 재생성과 안전 fallback
4. 요약 출처·정책·fallback 진단 정보를 저장하는 Room 4→5 migration
5. 결과 카드의 최신 결과·실제 처리 방식·정책 버전 표시
6. 지속 보존용 `.qa`와 자동 테스트용 `.deviceTest` 빌드 분리
7. 단위·빌드·migration·Compose·격리 실기기 테스트

## 제외 범위

- SenseVoice 모델, VAD, PCM 변환 알고리즘 교체
- Qwen 모델 교체 또는 추가 모델 다운로드
- 클라우드·네트워크 기반 STT/LLM 추가
- 기존 녹음·전사·요약 레코드의 자동 삭제 또는 일괄 재작성
- 기존 `.qa` 패키지에 대한 connected runner, `adb uninstall`, `pm clear`
- PD20 또는 Samsung `R3CY40PXCAP` 이외 기기의 실기기 검증

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.
- 구현 중 발생한 이슈는 해당 Phase에서 수정하고 기록한다.
- 체크박스 상태를 실제 진행 상태와 맞게 업데이트한다.
- 문서에 없는 범위 확장은 하지 않는다.
- 요약 본문을 `take(...) + "…"` 방식으로 절단해 품질 검사를 우회하지 않는다.
- 요약 항목 수를 맞추기 위해 원문 조각이나 일반 문장을 추가하지 않는다.
- 원문·Qwen raw 출력은 실기기 로그·PC 증적·문서에 기록하지 않는다.
- 기존 `.qa` 패키지는 `adb install -r` 이외 설치·초기화 명령을 금지한다.
- 자동 instrumentation은 새 `.deviceTest` 대상에서만 수행한다.
- 실기기는 Samsung `SM-S931N` (`R3CY40PXCAP`)만 허용하고 PD20은 사용하지 않는다.

- [ ] 문장부호 없는 500자 이상 한국어 STT가 하나의 거대 문장으로 처리되지 않는다.
- [ ] 요약 본문에 `…`가 저장되지 않고 모든 항목이 완결된 문장 또는 완결된 명사구다.

- [ ] 제목-요약 및 요약 항목 사이의 의미 없는 반복을 거절한다.
- [ ] Qwen 요청 실패와 품질 실패를 구분하고 실제 저장 엔진·fallback 이유를 보존한다.
- [ ] 기존 레코드는 migration 후 그대로 유지되고 정책 버전이 없는 기존 결과로 표시된다.

- [ ] 테스트 완료 후 사용자 확인 앱은 결과 화면을 유지하며 자동 종료하지 않는다.
