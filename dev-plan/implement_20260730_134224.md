# implement_20260730_134224.md

작성 일시: `2026-07-30 13:42:24 KST`

이 문서는 완료 녹음 파일이 SenseVoice 전사 과정에서 중간·끝 구간을 잃는 문제를
수정하고, 전사 완전성을 통과한 결과만 요약하도록 하는 개발 범위를 고정한다.

## 개발 목적

- 완료 녹음의 PCM 전체 길이가 STT 처리 범위에 포함되도록 보장한다.
- 28초 강제 분할 경계와 파일 끝에서 단어·음절이 잘리는 문제를 줄인다.
- 빈 구간, 구두점뿐인 결과, 비정상적으로 낮은 전사 밀도를 성공으로 저장하지 않는다.
- 낮은 품질 결과는 안전한 2차 전사 후에도 기준을 통과하지 못하면 요약을 실행하지 않는다.
- 세그먼트 범위·글자 수·재시도·완전성 판정을 세션에 저장해 결과를 설명 가능하게 한다.
- 기존 Samsung `.qa`의 녹음·모델·기존 결과를 보존한 상태에서 45초 원본을 다시
  전사·요약해 수정 효과를 검증한다.

## 개발 범위

1. SenseVoice 강제 분할에 1초 문맥 중첩과 마지막 무음 패딩 적용
2. 입력 길이 대비 세그먼트 범위·전사 밀도 품질 검사
3. 누락/저밀도 발생 시 전체 PCM 중첩 고정 청크 1회 재전사
4. 2차 처리도 실패하면 전사 품질 부족 상태로 종료하고 요약 차단
5. Room에 STT 진단 정보와 품질 상태 저장 및 비파괴 migration
6. 결과 화면에 전사 완전성·재처리 여부·실제 범위 표시
7. 생성 요약 제목의 원문 근거 검사와 재생성/안전 대체
8. 단위·Room·Compose·빌드 및 고정 Samsung 기존 45초 원본 재처리 검증

## 제외 범위

- SenseVoice 모델 파일 교체 또는 외부 STT·LLM·클라우드 추가
- 기존 녹음 원본, 설치 모델, 기존 전사·요약 기록 삭제
- 사용자가 선택하지 않은 전체 녹음의 일괄 재처리
- 요약 모델 자체 교체와 품질 정책 전면 재설계
- `com.thinktank.recorder.next.qa` 대상 uninstall, `pm clear`, connected instrumentation
- Samsung `SM-S931N` (`R3CY40PXCAP`) 이외 실기기 사용

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.
- 구현 중 발생한 이슈는 해당 Phase에서 수정하고 기록한다.
- 체크박스 상태를 실제 진행 상태와 맞게 업데이트한다.
- 문서에 없는 범위 확장은 하지 않는다.
- 기존 프로젝트 API와 sherpa-onnx 런타임을 유지하며 새 네트워크 의존성을 추가하지 않는다.
- 재전사는 같은 로컬 PCM을 최대 1회만 사용해 무한 재시도와 발열을 막는다.
- 전사 품질 실패를 정상 완료나 요약 성공으로 표시하지 않는다.
- 원본 녹음과 모델 파일은 읽기 전용으로 사용하고 임시 snapshot/PCM만 정리한다.
- 실기기 작업은 Samsung `R3CY40PXCAP`에서만 수행한다.
- `.qa` 업데이트는 동일 서명 APK의 `adb install -r`만 허용한다.
- 자동 instrumentation은 격리된 `.deviceTest`에만 실행한다.
- 원문과 모델 raw 출력은 계획 문서·상시 로그에 기록하지 않는다.
