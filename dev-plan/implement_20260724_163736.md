이 문서는 전사 완료 녹음마다 30-IDEAS에 확인 가능한 메모 1건을 남기고, 기존 LAN
Receiver 대시보드에서 MD 원문 보기와 수신 M4A 재생을 추가하기 위한 작업 문서다.

## 개발 목적

- 전사·정리까지 완료된 녹음은 LLM 추출 항목이 0개여도 `30-ideas`에 녹음별 메모를 정확히 1건 생성한다.
- 대시보드에서 노트를 선택해 MD 원문을 확인한다.
- 대시보드에서 사용자 범위의 수신 M4A를 인증된 요청으로 받아 재생한다.

## 개발 범위

- 전사 완료(`extracted → organized`) 녹음별 멱등 `recording_memo` 노트 렌더러와 저장 경로
- 기존 `30-ideas` 폴더·앱 노트 동기화 정책을 그대로 사용하는 생성 흐름
- `/api/v1/dashboard/notes/{folder}/{name}` 읽기 API와 MD 보기 패널
- `/api/v1/dashboard/audio/{filename}` 읽기 API와 선택한 M4A의 브라우저 재생 UI
- 기존 bearer 인증·사용자 격리·정적 대시보드만 유지하는 테스트와 문서 갱신

## 제외 범위

- 외부 클라우드, CDN, 스트리밍 서버 또는 별도 웹 서비스 추가
- 원문 전사에 근거 없는 AI 아이디어·할 일 생성
- 원본 M4A 삭제·이동·보존 기간 변경

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트를 통과한 뒤에만 시작한다.
- 기존 receiver 프로세스와 LAN 수신 구성을 유지하고, 토큰·절대 경로·음성 원문을 로그나 계획 문서에 기록하지 않는다.
- MD/오디오 요청은 bearer 인증으로 사용자 범위를 결정하며, 파일명·폴더는 안전한 leaf name과 허용 목록으로 검증한다.
- 브라우저 저장소에는 기존 receiver token만 세션 단위로 둔다. 토큰을 URL·HTML·API 응답에 넣지 않는다.
- 녹음별 메모는 전사 원문을 참조하는 사실 기록이며, LLM이 추출하지 못한 내용을 아이디어로 꾸며내지 않는다.
- 체크박스와 이슈 기록은 실제 결과에 맞춰 갱신한다.
