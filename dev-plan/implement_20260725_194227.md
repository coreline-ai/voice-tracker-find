## 서버·네트워크 조건부 후속 Workstream

이 Workstream은 Android 온디바이스 release를 막지 않는다. 실제 배포 프로필을
선택했을 때 해당 항목만 별도 계획으로 실행한다.

### 공통 최소 변경

- [x] legacy `/apk?token=` raw bearer를 기본 비활성화한다.
- [x] `scripts/run_receiver.ps1`와 `SETUP.md`에서 raw token URL 출력을 제거한다.
- [x] 3xx 응답 후 다른 host에 두 번째 요청과 Authorization 전달이 0건인지 테스트한다.

### standalone Receiver 직접 노출 시

- [ ] 전체 동시 요청을 16~32개로 제한하고 초과 요청에 `503 + Retry-After`를 반환한다.
- [ ] `native_tls`, `insecure_debug` 실행 프로필을 분리한다.
- [ ] non-loopback production listener는 TLS 없이 시작하지 않는다.
- [ ] 인증 실패 rate limit은 공용망에 직접 노출할 때만 추가한다.

### reverse proxy·managed ingress 사용 시

- [ ] `trusted_proxy` 프로필에서만 내부 HTTP를 허용한다.
- [ ] public CA HTTPS와 Android 기본 trust를 사용한다.
- [ ] concurrency·rate limit은 ingress 정책을 우선한다.

### 브라우저 APK 설치를 유지할 때만

- [ ] Bearer로 발급하는 128-bit 이상 난수 ticket과 Android 발급 GUI를 함께 설계한다.
- [ ] 짧은 TTL, 사용자·APK SHA-256 결합, 원자적 1회 소비를 적용한다.
- [ ] `Cache-Control: no-store`와 만료·재사용 테스트를 추가한다.

### self-signed LAN을 제품 요구로 확정할 때만

- [ ] 특정 host 전용 client에 정확한 인증서를 trust anchor로 등록한다.
- [ ] 기본 hostname 검증을 유지한다.
- [ ] 선택적으로 SPKI를 추가 검증한다.
- [ ] trust-all과 hostname verifier 우회를 금지한다.

## 전문가 최종 승인

초안의 방향은 타당했지만 서버 보안 항목을 무조건적인 release blocker로 둔 부분과
이미 구현된 모델 lock을 다시 개발하는 부분은 과도했다. 위와 같이 필수 Android
안정화 7개 항목과 배포 프로필별 조건부 서버 Workstream으로 분리한 뒤 최종 승인한다.
