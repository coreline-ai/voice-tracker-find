# implement_20260802_190531.md

작성 일시: `2026-08-02 19:05:31 KST`

이 문서는 독립 Android OAuth LLM SDK를 별도 저장소·별도 artifact로 개발하고,
ThinkTank Android 앱이 공개 API만 소비해 `OAuth Provider 우선 → 온디바이스 Gemma 폴백`
정책을 구현하기 위한 범위를 고정한다.

## 개발 목적

- 기존 `alpine-llm-gateway` 또는 ThinkTank 내부 코드에 종속되지 않는 독립 SDK를 만든다.
- SDK는 사용자의 Anthropic, Codex, xAI 계정 연결과 토큰 수명주기, Provider 요청 변환만 담당한다.
- ThinkTank는 SDK 내부 구현이나 토큰에 접근하지 않고 공개 API와 typed result/error만 사용한다.
- OAuth 계정이 없거나 원격 요약이 실패하면 ThinkTank가 온디바이스 Gemma를 사용한다.
- SDK와 ThinkTank의 버전·라이선스·배포·테스트를 독립적으로 관리한다.
- SDK에 PRoot, talloc, Alpine runtime, OpenMinis 소스, Compose, Hilt, Room, Gemma를 포함하지 않는다.

## 개발 범위

1. 별도 저장소 `oauth-llm-sdk-android`와 proprietary 라이선스·provenance 구성
2. Android/Kotlin 소비자와 호환되는 SDK Gradle 빌드 및 private Maven publication
3. Provider 중립 공개 API와 바이너리 호환성 기준
4. PKCE/state/nonce, Custom Tabs, loopback callback, 토큰 교환·refresh·logout
5. Android Keystore 기반 암호화 저장과 다중 사용자 profile 관리
6. Anthropic, Codex, xAI OAuth/inference adapter
7. Provider 중립 text generation API와 typed/redacted error
8. SDK sample 앱, testkit, MockWebServer·Robolectric·instrumentation·실계정 E2E
9. ThinkTank `feature-cloud-summary` 모듈과 Hilt adapter
10. ThinkTank cloud-first/local-fallback router, DB provenance, 설정·연결 UI
11. dependency verification, third-party notices, SBOM, release artifact 검증

## SDK 공개 API v1 제안

```kotlin
// oauth-llm-api: Android framework에 의존하지 않는 계약
interface LlmSessionClient : Closeable {
    val connections: StateFlow<List<LlmConnection>>

    suspend fun generate(
        profileId: String,
        request: LlmGenerateRequest,
    ): LlmGenerateResult

    suspend fun disconnect(profileId: String): DisconnectResult
}

// oauth-llm-android: Android Activity Result 연결 표면
interface AndroidOAuthLlmClient : LlmSessionClient {
    fun createConnectIntent(request: ConnectRequest): Intent

    suspend fun completeConnect(resultData: Intent?): ConnectResult
}
```

```kotlin
data class LlmGenerateRequest(
    val operationId: String,
    val model: String,
    val messages: List<LlmMessage>,
    val maxOutputTokens: Int,
    val responseSchema: JsonResponseSchema? = null,
    val timeoutMillis: Long,
)

data class LlmGenerateResult(
    val profileId: String,
    val provider: LlmProvider,
    val model: String,
    val text: String,
    val usage: LlmUsage?,
    val providerRequestId: String?,
    val latencyMillis: Long,
)
```

공개 API는 access token, refresh token, authorization code, raw HTTP request/response를 반환하지
않는다. Provider endpoint와 authorization header 조립도 SDK 내부에 유지한다.

### 연결 API 수명주기

- ThinkTank는 SDK가 제공하는 `ActivityResultContract` 또는 connect `Intent`만 실행한다.
- SDK 소유 `OAuthConnectActivity`가 browser launch, callback, token exchange를 관리한다.
- 회전·백그라운드 복귀 상태는 SDK ViewModel과 암호화 pending transaction으로 보존한다.
- 고정 localhost callback Provider는 SDK loopback transport를 사용한다.
- App Link/custom scheme을 허용하는 Provider는 AppAuth transport를 우선 사용한다.
- 프로세스 종료 후 복구 불가능한 Provider callback은 `AUTH_FLOW_INTERRUPTED`로 종료하고 재로그인한다.
- SDK result에는 토큰 대신 `profileId`, Provider, 표시 가능한 검증된 account metadata만 포함한다.

### 오류 계약

```kotlin
sealed class OAuthLlmFailure(
    open val retryable: Boolean,
    open val fallbackEligible: Boolean,
) {
    data object NotConnected : OAuthLlmFailure(false, true)
    data object AuthenticationRequired : OAuthLlmFailure(false, true)
    data object NetworkUnavailable : OAuthLlmFailure(true, true)
    data class RateLimited(
        val retryAfterMillis: Long?,
    ) : OAuthLlmFailure(true, true)
    data object ProviderUnavailable : OAuthLlmFailure(true, true)
    data object Timeout : OAuthLlmFailure(true, true)
    data object InvalidProviderResponse : OAuthLlmFailure(false, true)
    data object InvalidRequest : OAuthLlmFailure(false, false)
    data object UserCancelled : OAuthLlmFailure(false, false)
}
```

- `NotConnected`, refresh 실패, network, 429, 5xx, timeout, 유효하지 않은 Provider 응답은 로컬 폴백 가능
- `UserCancelled`, 앱 lifecycle cancellation, 잘못된 입력은 폴백 불가
- raw Provider body는 exception message와 앱 로그에 포함하지 않는다.
- 401은 SDK 내부 refresh 1회 후 최종 실패를 반환한다.
- 429와 5xx 재시도는 최대 횟수와 전체 시간 예산 안에서만 수행한다.

## ThinkTank 라우팅 계약

```text
요약 요청
  → 사용자가 선택한 활성 OAuth profile 확인
  → 없음: Gemma 로컬 실행
  → 있음: SDK generate
      → 성공: remote 결과 검증·저장
      → fallbackEligible 오류: Gemma 로컬 실행
      → 사용자 취소/입력 오류: 전체 요청 종료
```

- 연결된 Provider가 여러 개여도 자동으로 다른 Provider에 원문을 전송하지 않는다.
- 원격 경로는 현재 Gemma 700자 입력 builder를 재사용하지 않고 token-aware 전체 전사를 사용한다.
- 로컬 폴백은 현재 결정적 700자/계층형 Gemma 경로를 사용한다.
- DB에는 `requestedEngine`, `actualEngine`, `providerId`, `modelId`, `fallbackReason`, `dataPolicy`를 저장한다.
- UI에는 `Codex 실패 → 온디바이스 요약`처럼 실제 실행 결과를 표시한다.

## 잔여 리스크 / 후속 과제

- Provider의 callback·scope·endpoint 계약 변경은 SDK patch/minor release로 관리한다.
- 고정 loopback callback은 Android 프로세스 종료 시 완전 복구가 불가능할 수 있으므로 실기기
  결과에 따라 device authorization 또는 Provider가 허용하는 App Link로 전환한다.
- 세 Provider의 모델 목록은 SDK 상수로 무한 확장하지 않고 ThinkTank 검증 모델 allowlist로
  관리한다.
- v1 이후 custom Provider, streaming, tool calling, image input은 별도 계획 없이는 추가하지 않는다.
- SDK가 여러 앱에서 사용되면 Provider artifact 분리와 다중 소비자 호환 matrix를 별도 계획한다.
