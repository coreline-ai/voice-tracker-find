# implement_20260802_204022.md

작성 일시: `2026-08-02 20:40:22 KST`

이 문서는 ThinkTank 녹음 Android 앱에 독립 OAuth LLM SDK를 실제 Maven artifact로
연결하고, 클라우드 우선·Gemma 폴백 요약을 구현하는 범위를 고정하기 위한 작업 문서다.

## 개발 목적

- ThinkTank가 독립 SDK `ai.coreline.oauthllm:oauth-llm-android:0.1.0`만 소비하도록 한다.
- 사용자가 연결하고 활성화한 Anthropic, Codex, xAI 계정으로 전사 요약을 먼저 시도한다.
- typed 실패 정책이 허용할 때만 기존 Gemma 로컬 요약으로 폴백한다.
- 실제 실행 엔진, Provider/model, 요청 ID, 지연시간, 사용량, 폴백 사유를 저장·표시한다.

## 개발 범위

- `android-app/local-maven`의 재현 가능한 SDK 0.1.0 artifact 소비
- `feature-cloud-summary` 모듈, 구조화 요약 prompt/schema/parser, SDK adapter
- 공개 client ID와 model ID의 build-time 주입, 계정 연결·해제·활성 profile 선택 UI
- 기존 짧은/수동 요약 경로의 OAuth 우선·로컬 폴백 라우팅
- Room provenance migration과 결과 UI
- 단위 테스트, lint, debug/release APK build, secret/native payload 점검
- 실계정 E2E 보고서 템플릿과 실행 런북

## 제외 범위

- 독립 SDK 소스 수정 또는 sibling source Gradle dependency
- client secret, API key, token, authorization code, PKCE verifier 저장·표시·로그
- 오디오 원본 원격 전송
- Provider A 실패 후 Provider B로 자동 전환
- Compose/Hilt/Room/Gemma/SenseVoice를 독립 SDK에 추가
- 실계정 자격 증명이 없는 상태에서 E2E 완료 주장
- 장시간 계층형 Gemma checkpoint 알고리즘 자체의 재설계

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.
- 구현 중 발생한 이슈는 해당 Phase에서 수정하고 기록한다.

- 문서에 없는 범위 확장은 하지 않는다.

- 원격 성공·실패 모두 자동으로 다른 Provider를 시도하지 않는다.
- 기존 로컬 전용 동작과 `feature-ondevice` network boundary를 보존한다.
- 새 의존성은 artifact 소비에 필요한 항목만 추가한다.
